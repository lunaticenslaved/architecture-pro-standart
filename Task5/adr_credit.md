#### Система кредитов

Для реализации MVP кредитов был введён новый домен Система кредитов, реализованном через сикросервисную архитектуру.

Домен состоит из нескольких элементов:
1. Credit Service - управление заявками на кредиты с отдельной БД (PostgreSQL, Java)
1. Credit Database - хранит заявки и предодобренные кредиты
2. Pre-Approval Service - расчёт предодобренных приложений (Java), расчёт запускается ночью

Обоснование:

1. Возможность независимого развития и горизонтального масштабирования
2. Использование Java и Postgres как уже знакомые для IT-команды технологии

#### Интеграция с кредитным конвейером

##### Проблема

Заявки попадают в конвейер 1 раз в день

##### Решение

Добавить ручку в конвейер

```
POST /api/applications
```

1. Система кредитов получает заявку от клиента
2. Credit Service вызывает Credit Pipeline API
3. Credit Pipeline API создаёт новый процесс в Camunda
4. При изменении статуса заявки отправляется запрос в Credit Service
5. Credit Service изменяет статус и уведомляет клиента

##### Обоснование

1. Заявка обрабатывается за 1 день, а не за неделю
2. Бизнес-процессы остаются в Camunda


#### Ингерация с Системой скоринга

Система скоринга используется без изменений.

Для звщиты от перегрузки расчёты предодобренных кредитов выполняются ночью, а результаты кешируются в БД системы кредитов.


#### Технологический стек

| Сервис | Технологии | Обоснование |
| :- | :- | :- |
| Интернет-банк (фронтенд) | React 18 + TypeScript | Современные и знакомые технологии, удобство для пользователя |

| Pre-Approval Service | Java, Postgres 15+ | Экспертиза в IT-команде |


#### Интеграции

##### Синхронные (REST API):

- Интернет-банк -> Credit Service (подача заявки)
- Credit Service -> Кредитный конвейер (отправка заявки)
- Credit Service -> Система скоринга (быстрый скоринг для новых клиентов)
- Credit Service -> АБС API (данные клиента)
- Pre-Approval Service -> Система скоринга (фоновый расчет)
- Кредитный конвейер -> Система скоринга (детальный скоринг)

##### Асинхронные:

Кредитный конвейер -> Credit Service (изменение статуса заявки)

#### Безопасность

- HTTPS/TLS для всех внешних каналов
- OAuth 2.0 + JWT для аутентификации через API Gateway
- Read-Only доступ к АБС БД через API Layer
- Изоляция данных кредитов в отдельной БД
- Rate limiting на API Gateway
- Аудит всех операций с кредитными заявками

#### Масштабируемость

- Все новые сервисы поддерживают горизонтальное масштабирование
- Pre-Approval Service может масштабироваться через партиционирование клиентов

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

#### Вариант 1: Переписать Кредитный конвейер на микросервисы

##### Плюсы

1. Полный контроль над процессом
2. Новая архитектура

##### Минусы

1. Долгий процесс разработки
2. Риски потери бизнес логики

##### Вердикт

Отклонено из-за высоких рисков проблем с бизнес-логикой.


#### Вариант 2: Расчёты предодобренных предложений по запросу клиента

##### Плюсы

1. Меньшее количество микросервисов
2. Не нужны фоновые процессы

##### Минусы

1. Долгий расчёт (5-10 секунд), то приводит к плохому UX
2. Повышенная нагрузка на Систему скоринга

##### Вердикт

Отклонено из-за высоких рисков перегрузки Системы скоринга.


#### Вариант 3: Хранить заявки на кредиты в АБС

##### Плюсы

1. Быстрая реализация

##### Минусы

1. Повышенная нагрузка на перегруженную БД АБС
2. Сложность изменений в АБС

##### Вердикт

Отклонено из-за высоких рисков перегрузки БД АБС.


#### Недостатки, ограничения, риски

##### Недостатки

1. Дублирование данных:

- Данные о заявках хранятся Credit Service
- Обработка заявок происходит в Кредитном конвейере
- Нужна сихронизация статусов

2. Зависимость от доработки Кредитного конвейера

- Необходимо добавить новый эндпоинт в систему:
- Долгие сроки доработки
- Зависимость от подрядчика

3. Сложность инфраструктуры:

- Новые компоненты требуют мониторинга
- Необходимо повысить квалификацию команд

##### Ограничения

1. Сохраняется долгая синхронизация заявок из АБС, которые подаются из отделений банка
2. Новые клиенты должны приходить в отделение для иденитфикации
3. Сохраняются ограничения Системы скоринга, которую нельзя запускать в рабочие часы


##### Риски

- Команда подрядчика не сможет доработать Кредитный конвейер вовремя
- Десинхрнизация статусов заявок в Кредитном конвейере и Credit Service
- Перегрузка Системы скоринга при расчётах предодобренных заявок


##### План снижения рисков

- Приоритизация доработок в Кредитном конвейере
- Постепенная выкатка Pre-Approval Service
- Мониторинг и алёртинг
- Обучение команды и ведение документации
