| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F  | Функциональные (Functionality) | |
| F1 | Сайтом могут пользоваться авторизованные и неавторизованные пользователи | Просматрировать сайт должен любой пользователь, но авторизованные пользователи могут получать персонифицированные предложения |
| F2 | Интернет-банком могут пользоваться только авторизованные пользователи | Интернет-банк является личным кабинетом пользователя |
| F3 | Пользователь авторизуется по номеру телефона и через одноразовый СМС-код | |
| F4 | На сайте новый клиент видит список доступных депозитов с актуальными ставками | |
| F5 | На сайте клиент может подать заявку на депозит, оставив свой номер телефона и Ф. И. О. | |
| F6 | Менеджеры отдела депозита могут просматривать данные о клиентах, оставивших заявку на депозит | |
| F7 | Менеджер бэк-офиса депозитов должен иметь возможность подтвердить, изменить или отклонить условия депозита по заявке из интернет-банка/сайта в АБС | |
| F9 | В интернет-банке клиент видит список доступных депозитов с актуальными ставками и персонализированные ставки лично для него | |
| F10 | В интернет-банке клиент, указав счёт и сумму депозита, может подать заявку на открытие депозита. Операцию необходимо будет подтвердить с помощью СМС-кода | |
| F11 | Функционал работы с СМС должен быть реализован в ядре системы силами команды банка | Сейчас такой функционал есть в АБС, но он требует доработки со стороны подрядчика, а этого лучше избежать | |
| F12 | Нужно реализовать функционал работы с депозитными ставками в АБС, чтобы отделы кредитов и депозитов могли работать с ними | Сейчас ставки по депозитам сейчас не ведутся нигде, кроме XLS-файлов |
| F13 | Клиент должен получить СМС-уведомления после подтверждения размера ставки и открытия депозита | |
| F14 | Клиенты должны иметь возможность подавать заявки на кредит в интернет-банке и на сайте | |
| F15 | На сайте новый клиент должен видеть предложение открыть кредит по некоторой ставке | |
| F16 | Полная информация об возможных условиях кредита должна храниться в Кредитном конвейере | |
| F17 | Клиент должен иметь возможность подать заявку, оставив свой номер телефона и Ф. И. О. | |
| F18 | Клиент должен иметь возможность подать заявку и сразу получить решение об одобрении или неодобрении ему кредита, оставив свой номер телефона и Ф. И. О и паспортные данные | Для этого нужно получить данные из системы скоринга. Но так как клиент новый, можно использовать только общие данные бюро кредитных историй |
| F19 | После подачи заявки клиенту должно приходить СМС о том, что нужно прийти в отделение для получения кредита и идентификации | |
| F20 | Менеджеры отдела кредитования могут просматривать данные о клиентах, оставивших заявку на кредит | |
| F21 | Менеджер бэк-офиса кредитования должен иметь возможность подтвердить, изменить или отклонить условия кредита по заявке из интернет-банка/сайта в АБС | |
| F22 | Менеджер отделения банка при обслуживании клиента должен иметь возможность подать новую заявку на кредит, либо продолжить работать с уже существующей заявкой | |
| F23 | В интернет-банке клиент должен видеть список доступных кредитов с актуальными условиями так же, как и на сайте | |
| F24 | В том случае, если по клиенту уже произошел скоринг и была рассчитана приемлемая сумма кредита, то в интернет-банке должно выводиться предодобренное предложение по кредиту | |
| F25 | После подачи заявки должно пересчитываться предодобренное предложение по кредиту, если ситуация изменилась, но уже по упрощённой процедуре | Такие заявки сотрудники обрабатывают быстрее |
| F26 | Просматривая предодобренную заявку на кредит в интернет банке, клиент, указав счёт зачисления средств и данные для подачи заявки, может отправить её в банк | |
| F27 | Операция на подачу заявки на кредит через интернет-банк подтверждается СМС-кодом | |
| F28 | Система должна обеспечивать возможность обработки заявок на кредит, поступивших из интернет-банка и с сайта без участия АБС как посредника | Сейчас заявки попадают в Кредитный конвейер раз в сутки из АБС. При этом ускорить обмен между базами и проводить его чаще невозможно |
| F29 | Нужно добавить информирование клиента по СМС об изменении статуса заявки на кредит | |
| F30 | Система должна хранить историю изменения статусов заявки (депозит/кредит) для возможности отслеживания | |
| F31 | Клиент, подавший заявку на депозит через сайт, должен получить звонок от менеджера кол-центра | |
| F32 | При подаче заявки на депозит через сайт должна передаваться чувствительная информация (ФИО, телефон), защищённая шифрованием | |
| F33 | Заявки, созданные на сайте или в интернет-банке, должны иметь уникальный идентификатор в рамках всей системы | |
| U | Удобство использования (Usability) | |
| U1 | Нужно придерживаться системы дизайна для приложений, которая принята в компании. Пользователи при работе должны видеть привычные цвета и брендированные элементы | |
| R | Надёжность (Reliability) | |
| R1 | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев | |
| R2 | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны | |
| R3 | АБС не должна участвовать в синхронной обработке новых заявок на депозиты/кредиты из интернет-банка для предотвращения перегрузки | Команда АБС утверждает, что база данных системы уже перегружена. Онлайн-подача заявок на большое количество продуктов может поставить под угрозу работоспособность банка |
| P | Производительность (Performance) | |
| P1 | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды. Сейчас с этим есть проблема: при проведении платежей некоторые справочные данные загружаются больше секунды | |
| P2 | В случае сбоев в ЦОД необходимо, чтобы сервисы выдерживали требуемую нагрузку | |
| P3 | Нужно предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД (Кроме АБС) | |
| P4 | Но нужно учитывать, что АБС может масштабироваться только вертикально из-за своей базы данных | |
| P5 | Кредитный конвейер и система кредитного скоринга разработаны с учётом возможного роста нагрузки и поддерживают горизонтальное масштабирование с работой 24/7 | |
| P6 | Интернет-банк должен поддерживать горизонтальное масштабирование и распределение запросов между несколькими серверами и ЦОД | |
| P7 | Время ответа системы скоринга при синхронном запросе с сайта не должно превышать 500 мс | |
| P8 | Система не должна выполнять предрасчёты скоринга в периоды пиковой нагрузки (рабочие часы) | Система кредитного скоринга очень важна для работы банка и испытывает повышенную нагрузку в рабочие часы, её не нужно нагружать дополнительными процессами по предрасчетам скорингов |
| S | Поддерживаемость (Supportability) | |
| S1 | Нужно предусмотреть разработку документации для дальнейшего расширения системы | |
| S2 | Также желательно, чтобы внутри банка уже была экспертиза — сотрудники понимали новые технологии хотя бы на уровне языков программирования | |
| S3 | При реализации функционала работы с СМС необходимо предусмотреть его расширяемость для других каналов уведомлений (push, email) | |
| S4 | Код новых модулей должен быть документирован в соответствии со стандартами банка | |
| +S | Безопасность (Security) | |
| +S1 | Все передачи чувствительных данных (ФИО, телефон, паспортные данные) между клиентским устройством и серверами банка должны шифроваться с использованием TLS 1.2+ | |
| +S3 | Доступ сотрудников к данным клиентов должен быть ограничен в соответствии с их ролями (депозиты не видят кредитные данные и наоборот) | |
| +S4 | Система должна логировать все действия с заявками (кто, когда, что сделал) для аудита | |
| +R | + Ограничения (Restrictions) | |
| +R1 | При доработках во всех системах нужно как можно больше использовать технологии, которые уже есть в банке | Например, базы данных MS SQL и Oracle. Можно развернуть новые технологии, но необходимо, чтобы они были совместимы с существующими платформами разработки |
| +R2 | Текущая версия платформы интернет-банка несовместима с Kafka | |
| +I | Интеграции (Integration) | |
| +I1 | Интернет-банк не должен интегрироваться напрямую с API АБС для новых процессов открытия продуктов | Из-за перегруженности АБС |
| +I2 | Передача заявок на кредит из интернет-банка/сайта в Кредитный конвейер должна осуществляться в обход АБС | Чтобы обойти суточную задержку |
| +I3 | При необходимости использования очередей сообщений следует применять Kafka (с учётом несовместимости с текущей версией платформы интернет-банка) | Лучшее решение для высоконагруженных систем |
| +I4 | Предусмотреть перевод интернет-банка на микросервисную архитектуру, но пока только в рамках задачи открытия депозитов | Для совместимости с Kafka |
