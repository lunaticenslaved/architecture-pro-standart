| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F  | Функциональные (Functionality) | |
| F1 | На сайте и в интернет-банке клиент видит список доступных депозитов с актуальными ставками и персонифицированные предложения (для интернет-банка) | |
| F2 | На сайте и в интернет-банке клиент может подать заявку на депозит оставив свой номер телефона и Ф. И. О. (для сайта) или указав сумму и счёт и подтвердив заявку через СМС-код (для интернет-банка) | |
| F3 | Сотрудники кол-центра могут просматривать заявки на депозит от новых клиентов, присматривать данные по клиенту, чтобы предложить особые условия клиенту, и звонить клиенту для обсуждения условий | |
| F4 | На сайте и в интернет-банке клиент видит список доступных кредитов с актуальными ставками. В интернет-банке также может выводиться предодобренное предложение по кредиту, это означает, что по клиенту в какой-то момент уже произошел скоринг и была рассчитана приемлемая сумма кредита | |
| F5 | На сайте клиент и в интернет-банке должен иметь возможность подать заявку на кредит. <br/><br/> **Для сайта**: нужно оставив свой номер телефона и Ф. И. О и паспортные данные (опционально); если указаны паспортные данные, то сразу получить решение об одобрении или неодобрении на основе данных из БКИ; после подачи заявки клиенту должно приходить СМС о том, что нужно прийти в отделение для получения кредита и идентификации. <br/><br/> **Для интернет-банка**: После подачи заявки на кредит по персонифицированному предложению скоринг должен происходить повторно, если ситуация изменилась, но уже по упрощённой процедуре. Такие заявки сотрудники обрабатывают быстрее. <br/><br/> Операция на подачу заявки на кредит подтверждается СМС-кодом | |
| F6 | Система должна выполнять кредитный скоринг при подаче заявки на кредит на основе данных о клиенте из системы скоринга (для старых клиентов) или банных из бюро кредитных историй (для новых клиентов) | |
| F7 | Полная информация об возможных условиях кредита должна храниться в Кредитном конвейере | |
| F8 | Должен быть реализован функционал работы со ставками, чтобы отделы кредитов и депозитов могли работать с ними | Сейчас ставки по депозитам сейчас не ведутся нигде, кроме XLS-файлов |
| F9 | Клиент должен получить СМС-уведомления о происшествии значимых событий (подтверждения размера ставки и открытия депозита, изменения статуса заявки) | |
| F10 | Менеджер отделения банка при обслуживании клиента должен иметь возможность подать новую заявку на кредит, либо продолжить работать с уже существующей заявкой | |
| U | Удобство использования (Usability) | |
| U1 | Нужно придерживаться системы дизайна для приложений, которая принята в компании. Пользователи при работе должны видеть привычные цвета и брендированные элементы | |
| U2 | Интерфейс работы должен быть максимально удобным для клиента | |
| U3 | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды. Сейчас с этим есть проблема: при проведении платежей некоторые справочные данные загружаются больше секунды | |
| U4 | Учитывая, что большая часть клиентов - это люди старшего возраста, то должен быть сохраняться канал обслуживания через кол-центр | |
| U5 | С учётом пункта U4 сотрудники кол-центра должны иметь доступ к информации о ставках для консультирования клиентов | |
| R | Надёжность (Reliability) | |
| R1 | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев | |
| R2 | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны, что можно обеспечить использованием нескольких ЦОД и автоскейлингом | |
| R3 | АБС не должна участвовать в синхронной обработке новых заявок на депозиты/кредиты из интернет-банка для предотвращения перегрузки на БД АБС, так как она уже испытывает значительные нагрузки |  |
| R4 | Система не должна давать повышенной нагрузки на систему кредитного скоринга в периоды пиковой нагрузки (рабочие часы), то есть предрасчёты скоринга должны выполняться в другое время |  |
| R5 | Нужно предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД (Кроме АБС). Нужно учитывать, что АБС может масштабироваться только вертикально из-за своей базы данных. Кредитный конвейер и система кредитного скоринга разработаны с учётом возможного роста нагрузки и поддерживают горизонтальное масштабирование с работой 24/7 |  |
| P | Производительность (Performance) | |
| P1 | Отклик по всем операциям должен быть максимально быстрым и занимать не более 200 мс. Сейчас с этим есть проблема: при проведении платежей некоторые справочные данные загружаются больше секунды | |
| P2 | Система должна обеспечивать равномерное распределение нагрузки между серверами приложений и ЦОД для предотвращения перегрузки отдельных узлов | |
| P3 | Время ответа системы скоринга при синхронном запросе с сайта не должно превышать 500 мс | |
| P3 | Заявки на кредит с предобренными условиями должна обрабатывать в течение одного для, а не недели, как сейчас | |
| P4 | Новые компоненты должны поддерживать горизонтальное масштабирование, чтобы выдерживать повышение нагрузки без деградации производительности | |
| P5 | Загрузка справочных данных должна занимать меньше 1 секунды (против > 1 секунды сейчас) | |
| S | Поддерживаемость (Supportability) | |
| S1 | Нужно предусмотреть разработку документации для дальнейшего расширения системы | |
| S2 | Также желательно, чтобы внутри банка уже была экспертиза — сотрудники понимали новые технологии хотя бы на уровне языков программирования, - поэтому лучше использовать текущие технологии (Oracle, MS SQL, Java, .NET, PHP) | |
| S3 | При реализации функционала работы с СМС необходимо предусмотреть его расширяемость для других каналов уведомлений (push, email) | |
| S4 | Архитектура новых модулей должна разрабатываться только внутри банка, без привлечения подрядчиков | |
| +S | + Безопасность (Security) | |
| +S1 | Все передачи чувствительных данных (ФИО, телефон, паспортные данные) между клиентским устройством и серверами банка должны шифроваться с использованием TLS 1.2+ | |
| +S3 | Доступ сотрудников к данным клиентов должен быть ограничен в соответствии с их ролями (депозиты не видят кредитные данные и наоборот) | |
| +S4 | Система должна логировать все действия с заявками (кто, когда, что сделал) для аудита | |
| +R | + Ограничения (Restrictions) | |
| +R1 | Текущая версия платформы интернет-банка несовместима с Kafka | |
| +R2 | Функционал работы с СМС должен быть реализован в ядре системы силами команды банка | Сейчас такой функционал есть в АБС, но он требует доработки со стороны подрядчика, а этого лучше избежать |
| +R3 | Система должна обеспечивать возможность обработки заявок на кредит, поступивших из интернет-банка и с сайта без участия АБС как посредника | Сейчас заявки попадают в Кредитный конвейер раз в сутки из АБС. При этом ускорить обмен между базами и проводить его чаще невозможно |
| +R4 | Партнёрский кол-центр может получать данные только через файлы (SFTP), API-интеграция невозможна | |
| +I | + Интеграции (Integration) | |
| +I1 | Интернет-банк не должен интегрироваться напрямую с API АБС для новых процессов открытия продуктов | Из-за перегруженности АБС |
| +I2 | Передача заявок на кредит из интернет-банка/сайта в Кредитный конвейер должна осуществляться в обход АБС | Чтобы обойти суточную задержку |
| +I3 | Предусмотреть переход на микросервисную архитектуру, но пока только в рамках задачи открытия депозитов | Для совместимости с Kafka |
