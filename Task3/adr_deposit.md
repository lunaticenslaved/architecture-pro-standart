### <a name="_qmphm5d6rvi3"></a>**Решение**

#### Система депозитов

Для реализации MVP депозитов был введён новый домен Система депозитов, реализованном через сикросервисную архитектуру.

Домен состоит из нескольких элементов:
1. Deposit Service - управление заявками на депозиты с отдельной БД (PostgreSQL, Java)
2. Rate Service - управление ставками с отдельной БД (PostgreSQL, Java)
3. Notification Service - отправка уведомлений (Java)
4. Admin UI - для управления заявками
5. Message Bus - использование событийной архитектуры для уведомлений

Обоснование:

1. Уход от зависимости от подрядчика
2. Возможность независимого развития и горизонтального масштабирования
3. Использование Java и Postgres как уже знакомые для IT-команды технологии 
4. Использование событийной архитектуры как способ снизить нагрузку на сервисы и повысить надёжность системы
5. Использование отдельной БД для системы депозитов снимет нагрузку с АБС БД

#### Интернет-банк

Предлагается реализовать новый интерфейс для управления депозитами на React SPA с BFF на PHP. 

Обоснование:

1. SPA предоставляет наиболее приятный опыт для пользователей.
2. Команда уже имеет опыт использования React и PHP
3. Новый интерфейс можно использовать в дальнейшем для сиграции с легаси-монолита на .NET
4. Независимость от подрядчика

#### API Gateway

Обочнование:

1. Централизованной аутентификации и авторизации
2. Балансировки нагрузки
3. Управления rate limiting

#### АБС API Layer

Тонкий слой REST API.

Обоснование:

1. Защита БД от прямого доступа
2. Предоставление API для операций чтения

#### Сервис уведомлений и очередь сообщений

Уведомления вынесены в отдельный сервис и реализованы через событийную модель.

Обоснование:

1. Снижение времени ожидания на выполнение операции
2. Возможность интегрировать новые транспорты для доставки уведомлений
3. Уход от СМС-функционала в ядре банка, который разрабатывает подрядчик


#### Технологический стек

| Сервис | Технологии | Обоснование |
| :- | :- | :- |
| Интернет-банк (фронтенд) | React 18 + TypeScript | Современные и знакомые технологии, удобство для пользователя |
| Интернет-банк (BFF) | PHP | Знакомые для команды технологии |
| API Gateway | Nginx + Kong | Балансировка нагрузки |
| Deposit Admin UI | React 18 + TypeScript | Современные и знакомые технологии |
| Deposit Service | Java, Postgres 15+ | Экспертиза в IT-команде |
| Rate Service | Java, Postgres 15+ | Экспертиза в IT-команде |
| Message Bus | Kafka | Подходит для больших нагрузок |
| АБС API | Java | Экспертиза в IT-команде |


#### Интеграции

##### Синхронные (REST API):

Интернет-банк -> Deposit Service (подача заявки)
Deposit Service -> Rate Service (расчет ставок)
Rate Service -> АБС API (данные клиента)
Deposit Service -> АБС API (проверка счетов)
Система кол-центра -> Deposit Service, Rate Service (просмотр заявок и ставок)


##### Асинхронные:

Deposit Service -> Message Bus -> Notification Service (отправка SMS)


#### Безопасность

HTTPS/TLS для всех внешних каналов
OAuth 2.0 + JWT для аутентификации через API Gateway
Read-Only доступ к АБС БД через API Layer
Изоляция данных депозитов в отдельной БД
Rate limiting на API Gateway


#### Масштабируемость

- Все новые сервисы поддерживают горизонтальное масштабирование
- АБС остаётся с вертикальным масштабированием


### <a name="_bjrr7veeh80c"></a>**Альтернативы**


#### Вариант 1: Доработка монолита Интернет-банка

##### Плюсы

- Быстрая реализация решения
- Малое использование инфраструктуры

##### Минусы

- Остаётся зависимость от подрядчика
- Невозможность использования Kafka
- Устаревшие технологии
- Неудобство для пользователей из-за устаревшего UI
- Сложность масштабирования

##### Вердикт

Отклонено из-за необходимости уменьшить зависимость от подрядчика


#### Вариант 2: Доработка АБС 

##### Плюсы

- Полная автоматизация без ручной работы бэк-офиса

##### Минусы

- Невозможность использования Kafka
- Устаревшие технологии
- Сложность масштабирования
- Дополнительная нагрузка на БД АБС


##### Вердикт

Отклонено из-за риска перегрузки БД АБС


#### Недостатки, ограничения, риски

##### Недостатки

1. Дублирование данных:

- Данные о заявках хранятся
- Открытые депозиты хранятся в АБС
- Нужна сихронизация общих данных

2. Отсутствие автоматизации по открытию депозитов:

- Сотрудники бэк-офиса выполняют двойную работу
- Риск человеческих ошибок

3. Сложность инфраструктуры:

- Новые компоненты требуют мониторинга
- Необходимо повысить квалификацию команд


##### Ограничения

- Отсутсвие полноценного горизонтального масштбанирования из-за поддержки легаси систем
- Зависимость выдачи депозита от доступности АБС


##### Риски

- Сопротивление команды применению новых технологий и обучению
- Проблемы с производительностью АБС API
- Сильное повышение количества используемых серверов
- Проблемы с синхронизацией данных


##### План снижения рисков

- Запуск MVP на ограниченное число пользователей
- Изпользование кэширования для снижения нагрузки на АБС
- Использование мониторинга и алёртинга для наблюдения за состояние серверов
- Обучение команды
